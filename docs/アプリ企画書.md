# Gitぱっち

Gitを始めた学生向けの、ペット育成つきGit活動記録アプリ。

## ねらい

コミットやpushが続かない人でも、ペットの成長を楽しみながらGitを使い続けられるようにする。

## 想定する人

**竜樹諒（19歳・情報系専門学生）**

- 授業でGitを使い始めたばかり
- コミットを忘れたり、開発が止まりがち
- 難しい操作より、結果が分かりやすい画面を求めている

## 最初に作る機能

| 機能 | できること |
| --- | --- |
| リポジトリ登録 | Gitリポジトリの名前とパスを登録する |
| 一覧・編集・削除 | 登録したリポジトリを管理する |
| Git活動の確認 | 最新コミットを確認してペットに経験値を与える |
| ペット表示 | レベル・経験値・機嫌を表示する |
| お世話 | なでる／ごはんをあげて、ペットの状態を変える |
| データ保存 | アプリを閉じても登録内容を残す |

## データ

| 名前                | 主な内容                 |
| ----------------- | -------------------- |
| Pet               | 名前、レベル、経験値、満腹度、機嫌    |
| RepositoryProfile | 表示名、パス、最新コミット、メイン設定  |
| Item              | ごはんの名前、価格、効果(作らないかも) |
| InventoryItem     | アイテムと所持数             |

## クラス案

| クラス                  | 種類  | 役割                  |
| -------------------- | --- | ------------------- |
| `Main`               | 起動  | アプリを起動する            |
| `Menu`               | UI  | メニューを表示して入力を受け取る    |
| `Pet`                | データ | ペットの状態を保持する         |
| `RepositoryProfile`  | データ | 登録したリポジトリ情報を保持する    |
| `Item`               | データ | ごはんの情報を保持する         |
| `InventoryItem`      | データ | 所持アイテムと数量を保持する      |
| `RepositoryService`  | 処理  | リポジトリのCRUDを行う       |
| `GitActivityService` | 処理  | Gitコマンドを実行して活動を確認する |
| `PetService`         | 処理  | EXP付与・レベルアップ・交流を行う  |
| `CsvStorage`         | 保存  | CSVへ保存し、CSVから復元する   |
## 処理の流れ
1. `Main` がアプリを起動する。
2. `Menu` がユーザー入力を受け取る。
3. `RepoService` がリポジトリの登録・一覧・編集・削除を行う。
4. `GitActivityService` が登録済みリポジトリの最新コミット情報を確認する。
5. Git活動が確認できたら、`Pet` に経験値を追加する。
6. `CsvService` がペット状態とリポジトリ情報をCSVに保存する。

## レビューで見てほしいこと

1. 初心者が「登録 → Git活動確認 → ペット成長」を迷わず進められるか。
2. CRUD（登録・一覧/詳細・編集・削除）が過不足なく入っているか。
3. Gitの情報取得に失敗したとき、利用者に分かる案内が出せる設計か。
4. 発展機能を切り分けたことで、今回の制作範囲が大きくなりすぎていないか。


## 設計で意識すること

`Main` にすべての処理を書くと、入力、Git確認、ペット更新、CSV保存が混ざって読みにくくなる。  
そのため、入力は `Menu`、処理は `Service`、データ保持は `Pet` や `RepoProfile` に分ける。  
画像の `Main → Service → Model` の形に近づけることで、あとから機能を増やすときも修正しやすくする。
