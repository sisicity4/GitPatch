# Gitぱっち 発展要素 学習シート

## このシートの目的

Gitぱっちの現在のコードには、授業で学んだ基本文法に加えて、少し発展したJavaの記法やAPIが使われている。このシートでは、それぞれの役割と基本文法とのつながりを確認する。

> このファイルは `docs/` にあるため、Gitで管理される。授業参考資料は `docs/ex/Java授業参考資料/` を参照する。

> ## 学習カード 1：授業で学んだ土台
>
> **学ぶこと：クラスの役割分担、カプセル化、制御文、例外処理、コレクション**

Gitぱっちは、授業で学んだJavaの基本を組み合わせて作っている。

`Pet` はペットの状態を持つクラス、`PetService` は状態を変更するルールを持つクラス、`Menu` は画面表示と入力を担当するクラスである。この分け方は、`AI展開資料/08-oop-classes.md` の「クラスごとに役割を分ける」考え方に対応している。

`Pet()` や `RepositoryProfile(String, String)` はコンストラクタ、`private` フィールドとgetterはカプセル化、`if`・`while`・`switch` は制御文、`try-catch` は例外処理、`List<RepositoryProfile>` と `ArrayList` はコレクションの学習内容である。

**確認ポイント：** 発展した書き方を使っていても、アプリの基本は授業で学んだJavaでできている。

> ## 学習カード 2：`enum` で表情を管理する
>
> **学ぶこと：決まった候補を型として扱う**

**使っているコード：** `src/Pet.java`

```java
public enum Expression {
    HUNGRY, SAD, HAPPY, NORMAL
}
```

`enum` は、決まった候補だけを扱うための型である。Gitぱっちでは、ペットの表情を `HUNGRY`、`SAD`、`HAPPY`、`NORMAL` の4種類に限定している。

文字列で表情を管理すると、`HAPPY` のつもりで `HAPYY` と書いても、Javaはすぐに間違いだと判断できない。`enum` を使うと、存在しない表情名はコンパイルエラーになる。

```java
Pet.Expression expression = Pet.Expression.HAPPY;
```

**授業とのつながり：** クラス・型・カプセル化の考え方を発展させた書き方。

**確認ポイント：** 表情の追加やGUI化をするときも、表情の種類を1か所で管理できる。

> ## 学習カード 3：矢印形式の `switch`
>
> **学ぶこと：分岐の書き忘れを減らす**

**使っているコード：** `src/Menu.java`

```java
switch (input) {
case "1" -> showPetStatus();
case "2" -> feedPet();
case "3" -> strokePet();
default -> System.out.println("0〜3の番号を入力してください。");
}
```

授業でよく使う書き方では、`case:` と `break` を使う。

```java
switch (input) {
case "1":
    showPetStatus();
    break;
default:
    System.out.println("0〜3の番号を入力してください。");
    break;
}
```

矢印形式では、`break` を書き忘れて次のcaseまで実行してしまう失敗を防ぎやすい。Java 21で使える書き方である。

また、`faceOf` と `statusMessageOf` では、`switch` の結果を直接返している。

```java
return switch (expression) {
case HUNGRY -> "(´；ω；`)";
case SAD -> "(｡•́︿•̀｡)";
case HAPPY -> "(＾▽＾)";
case NORMAL -> "(・ω・)";
};
```

**授業とのつながり：** `switch` は `AI展開資料/05-control-flow.md` の内容。矢印形式はJava 21の発展的な書き方。

> ## 学習カード 4：`Math.clamp` で状態を0〜100に保つ
>
> **学ぶこと：値の範囲を守る**

**使っているコード：** `src/Pet.java`

```java
this.hunger = Math.clamp(hunger, 0, 100);
```

`Math.clamp(値, 最小値, 最大値)` は、値を指定範囲に収めるJava 21のAPIである。満腹度が `-10` なら `0`、`120` なら `100` になる。

同じ処理は、授業で学ぶ `if` と比較演算子だけでも書ける。

```java
if (hunger < 0) {
    this.hunger = 0;
} else if (hunger > 100) {
    this.hunger = 100;
} else {
    this.hunger = hunger;
}
```

**授業とのつながり：** 比較演算子と `if` は `AI展開資料/04-operators-input.md`、`05-control-flow.md` の内容。

**確認ポイント：** `Math.clamp` は短く書くための便利APIであり、考え方の中心は条件分岐である。

> ## 学習カード 5：`final` で参照の入れ替えを防ぐ
>
> **学ぶこと：途中で変えてはいけないものを表す**

**使っているコード：** `src/Menu.java`

```java
private final Scanner scanner;
private final Pet pet;
private final PetService petService;
```

`final` を付けると、コンストラクタで受け取った `Pet` や `PetService` を、あとから別のインスタンスに入れ替えられない。

これは「このMenuは、作られたときに渡されたペットとサービスを使い続ける」という約束をコードで表している。

ただし、`final Pet pet` はペットの満腹度や機嫌まで変わらないという意味ではない。変更できないのは、`pet` が指すペットを別のペットへ入れ替えることである。

**確認ポイント：** `final` は「オブジェクトの中身を変更不可にする」ものではなく、「参照の再代入を禁止する」もの。

> ## 学習カード 6：`List.copyOf` で一覧を守る
>
> **学ぶこと：Serviceの内部データを外部から守る**

**使っているコード：** `src/RepositoryService.java`

```java
public List<RepositoryProfile> findAll() {
    return List.copyOf(repositories);
}
```

`List` と `ArrayList` はコレクションの授業内容である。`List.copyOf` は、Serviceが持つ本物の一覧を直接渡さず、コピーを返すための書き方である。

こうしておくと、画面側のコードが一覧を直接追加・削除しても、`RepositoryService` の内部一覧は変わらない。登録・編集・削除は、`RepositoryService` のメソッドに集められる。

**授業とのつながり：** `List`、`ArrayList`、ジェネリクスは `AI展開資料/11-collections.md` の内容。`List.copyOf` はカプセル化をさらに意識した発展的な使い方。

> ## 学習カード 7：`--test` でテスト起動する
>
> **学ぶこと：実行時の引数を使って動作を切り替える**

**使っているコード：** `src/Main.java`

```java
if (args.length > 0 && "--test".equals(args[0])) {
    testPetService();
    return;
}
```

通常起動ではメニューを開き、`--test` を付けたときだけペット機能のテストを実行する。

```sh
# 通常起動
java -cp bin Main

# テスト起動
java -cp bin Main --test
```

`args` は、`main(String[] args)` に渡される文字列の配列である。先に `args.length > 0` を確認しているため、引数なしで起動しても `args[0]` を読もうとしてエラーになることはない。

テストでは、期待値と実際の値が違うときに `AssertionError` を出して止める。

```java
throw new AssertionError(testName + "：期待値=" + expected + "、実際=" + actual);
```

**確認ポイント：** これはJUnitを使わずに、今の段階で動作確認をしやすくするための簡易テストである。

> ## 学習カード 8：これから必要になる発展内容
>
> **学ぶこと：ファイル操作と外部コマンド実行**

`GitActivityService` と `CsvStorage` は、現在は空のクラスである。

`GitActivityService` では、JavaからGitコマンドを実行するために `ProcessBuilder`、標準出力・標準エラー出力、終了コード、`IOException`、`InterruptedException` を扱うことになる。

```text
Java
  ↓
git -C <path> log -1 --format=%H
  ↓
最新コミットIDを取得する
```

Gitの概念は `AI展開資料/01-git-github.md` を参照する。Javaから外部コマンドを実行する部分は、授業の基礎から発展した内容である。

`CsvStorage` では、ファイルの読み書き、文字列分割、数値変換、`IOException`、壊れたデータへの対応が必要になる。例外処理の基礎は `AI展開資料/10-exceptions.md` を参照する。
